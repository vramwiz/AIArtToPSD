## 手法と検証

入力は今回の文書の頭部272×255、配置(366,19)。冷色の髪と暖色の肌の判別、目視した毛束の境界、顔輪郭の小成分を用いた、この原画専用の分離。元の47,671可視画素を一つずつ前髪・横髪、顔・首、見えていた後ろ髪へ割り当てた。アプリ出力との照合で元画素の欠落・重複・RGBA変更はすべて0。

内蔵image_genを1回使用し、肌や顔を含まない連続した後ろ髪を生成した。指示全文は [prompt.json](prompt.json)、未加工出力は [rear_hair_generated.png](rear_hair_generated.png)。画像生成内部モデルは未特定。見える元画素は再生成画像で置き換えず、生成画像を遮蔽領域へマスクして背面へ配置した。頭頂の前髪用の跳ね毛を後ろ髪へ重複させないため、生成補完の上端を内側へ制限した。

生成1295×1214から272×255への拡縮と透明余白除去はアプリが実行。後ろ髪は元の側面・毛先と生成補完を2レイヤーで保持する。中央の確認領域に顔形の透明穴はなく、アプリ出力の最小alphaは251。毛先の自然な隙間は残る。

既存40画像のPNGハッシュ・配置・属性を保持し、意図した元頭部の表示だけ変更した。追加した4画像も表示切替前後で同一。実際の合成画像では頭部領域外の変更は0。頭部は元画像が完全不透明ではないため、背面補完がわずかに透過し、全RGBA一致ではない。33,902画素で差があり、RGB差の最大10、alpha差の最大35、変更画素の最大RGB差平均は約0.400/255。[明暗背景比較](app_comparison.png)も確認した。

## 制約

- 後ろ髪の隠れた形状・毛流れは推定生成。原画にない部分の正解を復元したとは扱わない。
- 元の後ろ髪との色・毛流れの接続、前髪と後ろ髪の境界はユーザー確認待ち。
- 顔レイヤーは見えていた肌だけ。前髪の下の額・頭皮・耳などは今回補完していない。前髪を外すと顔の上端が前髪の形になる。
- 分離マスク・座標・暖色判定はこの原画専用。他キャラへ無条件に流用しない。
- 元の薄いアルファ画素は保持している。後ろ髪を背面に置くことで半透明部分の合成結果が微小に変わる。

スクリプトは当時のExchangeと文書IDを参照する再現記録であり、現在文書へそのまま再送しない。次の編集は新しいstatus/exportから開始する。

検査中に毛先まで含めた不透明度チェックとGDI+経由の画素照合で検査方法上の不一致が出た。前者は毛先の隙間と中央の穴を分け、後者は直接RGBAを比較するよう修正した。最終の中央領域・原画素保持検証は合格。元画像や採用素材を修正して検査を通したものではない。
