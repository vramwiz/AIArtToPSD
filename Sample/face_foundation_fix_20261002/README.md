## 制作と検証

内蔵image_genを1回使用し、髪・目・眉・口のない、額と頭頂まで連続した肌素体を生成した。[指示全文](prompt.json)、[未加工生成画像](skin_generated.png)、[入力頭部](head_reference.png)、[修正前の肌](face_before.png)を保持。画像生成内部モデルは未特定。

生成1295×1214をアプリで272×255へ縮小し、元頭部から(+8,+15)の位置で鼻・顎の位置を合わせた。アプリ出力から額・頭部・耳・頬上部を採用し、頭部内y=180～199で元の下顔へ接続。元の鼻の小領域も再利用した。キャンバスy=219以降の顎・首は既存画素を保持し、以前の色判定で抜けていた顎の白いハイライト2画素を元頭部のRGBAから復元した。白い画素を透明背景として扱わない。

前髪を重ねると、前回の分離で肌側へ割り当てた髪の境界画素が切断面として現れたため、元頭部を参照して肌／髪境界だけの色・アルファを補正した。頭部内x=65～227、y=75～184の境界1,921画素を変更し、790画素を髪側へ回収。この範囲全体を描き直したわけではない。肌側に髪の跡を残す処理ではない。

アプリ出力の可視RGBAと準備画像の不一致は、肌・前髪とも0。肌のalpha<128領域を外周から8近傍で調べ、閉じ込められた透明画素は0。額から顔の中央の低アルファ画素も0。その他42画像の不変を検証した。詳細は [verification.json](verification.json)、[app_pixel_verification.json](app_pixel_verification.json)。

## 制約と再利用

額・頭部・耳の補完は推定生成で、元の顔全体との画素一致は主張しない。今回の色合い、前髪の縁、耳との接続を含む修正結果はユーザー確認・採用済み。前髪を動かす診断は20px平行移動の例であり、任意の回転・変形や別原画への汎用性の保証ではない。同じPSD内に残る別試験の体ポーズ等まで採用済みと扱わない。

再利用する判断と順序は次のとおり。実際の座標・倍率・色判定・マスクは画像ごとに測り直す。

1. 現在の文書から新規exportし、髪・肌・表情レイヤーと表示状態を特定する。
2. 髪付き頭部を構図の参照、欠けた肌を問題の参照として、額・頭頂・こめかみまで連続した肌素体を生成する。独立レイヤーの目・眉・口は描かせない。
3. 鼻・顎・耳・首などの位置を測り、アプリで縮小・配置する。維持できる元画素は再利用し、必要な接続部だけをなじませる。
4. 肌に髪跡が残る場合は、元絵を参照して髪側へ境界画素を戻し、肌色の混入とアルファを限定補正する。通常合成を合わせるために肌へ髪を貼り付けない。
5. 肌単独・髪単独・元位置合成・髪移動時を確認する。白いハイライトの欠落と内部の透明穴も点検する。
6. revisionを確認して対象だけを差し替え、再exportで非対象画像・配置・属性・表示と出力RGBAを照合する。ユーザー確認後に成功として記録する。

この記録は後続のCodexが読むプロジェクト資料であり、モデル本体の学習更新や汎用自動分離プログラムではない。採用済み素材を再確認だけのために再生成する必要はない。
